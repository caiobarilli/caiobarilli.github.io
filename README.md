## What it is

A fully static site that presents my projects as case studies: the problem, the solution, the stack, the decisions behind it and real screenshots. Every claim on the site comes from the projects' own code, READMEs and documentation.

- **Projects:** PHParrot, PHPorto, Keeptask, an AWS platform built with Terraform, and earlier JavaScript and TypeScript work.
- **Experience:** roles, education and courses, with links to each company and course.
- **Two languages:** English by default (`/en/`) and Brazilian Portuguese (`/pt-br/`). The root page sends visitors to the language of their browser.
- **Light and dark themes** that follow the system preference and remember the visitor's choice.

## Technical highlights

- **Static export** with Next.js 16 (App Router) and `output: 'export'`: every route, including one page per project and language, is generated at build time. No server, no runtime API.
- **One content source:** all text lives in [`src/content/site.json`](src/content/site.json), typed in [`types.ts`](src/content/types.ts) and read through a single `getContent()` function, so pages never depend on where the content comes from.
- **Design tokens** from the design prototype ([`design/`](design/)) mapped to CSS variables and Tailwind 4 theme colours, with separate values for the dark and light themes.
- **Accessible UI:** skip link, visible focus, keyboard navigation, `lang` per locale, `prefers-reduced-motion`, and a screenshot lightbox built on the native `<dialog>` (focus trap, Esc, arrow keys, focus restored on close).
- **Images:** WebP screenshots generated by scripts with [sharp](https://sharp.pixelplumbing.com/), with all metadata (EXIF/GPS) stripped. The original files never enter the repository.
- **Supply chain:** GitHub Actions pinned to full commit SHAs, read-only permissions for the build job, and exact dependency versions in the lockfile.

## Running locally

Requirements: Node.js 24 and npm.

```sh
npm ci
npm run dev
```

Then open <http://localhost:3000/en/>.

### Working with coding agents

The repository ships an [`.mcp.json`](.mcp.json) with Vercel's [next-devtools-mcp](https://github.com/vercel/next-devtools-mcp), pinned to an exact version. With `npm run dev` running, an MCP-capable agent (such as Claude Code) can read the app's live errors, routes and logs through Next.js 16's `/_next/mcp` endpoint, and the documentation that matches the installed Next.js version.

[`.claude/skills/`](.claude/skills/) holds five agent skills from [mattpocock/skills](https://github.com/mattpocock/skills) (MIT, copied at commit `4ae2317`), so any agent that opens the repo follows the same workflow:

| Skill | Used for |
| --- | --- |
| `tdd` | Red → green loop with tests at agreed seams |
| `diagnosing-bugs` | A tight feedback loop before any hypothesis |
| `code-review` | Review against the repo's standards and against the spec, kept separate |
| `grilling` | Settling decisions one round of questions at a time |
| `handoff` | Passing the work to a fresh agent session |

## Scripts

| Command | What it does |
| --- | --- |
| `npm run dev` | Development server |
| `npm run lint` | ESLint with the Next.js core-web-vitals and TypeScript rules |
| `npm run typecheck` | `tsc --noEmit` in strict mode |
| `npm run test` | Vitest: content shape, same UI keys in every language, locale helpers |
| `npm run build` | Static export to `out/` |
| `npm run gate` | All four checks above, in order — the bar for every commit |

### Images

```sh
node scripts/photo.mjs "<path to original photo>"
node scripts/shots.mjs "<keeptask prints dir>" "<phparrot captures dir>"
```

`photo.mjs` crops the profile photo and writes `public/images/caio-96.webp` and `caio-480.webp`. `shots.mjs` turns project screenshots into 16:10 WebP files in `public/images/projects/`, including the side-by-side phone panels. A project screenshot that does not exist yet renders as a striped placeholder instead of breaking the page.

## Structure

```text
src/
  app/
    [locale]/              pages per language: home, projects, project/[slug], experience, about, contact
    global-not-found.tsx   static 404 for GitHub Pages
    globals.css            design tokens and Tailwind theme
  components/              header, project grid, screenshot, lightbox, theme script
  content/                 site.json (all text), types and the getContent() helpers, tests
public/
  index.html               language redirect for the root URL
  images/                  generated WebP images
design/                    design prototype, tokens and the AWS architecture diagram (SVG)
scripts/                   image generation
```

## Deployment

Every push and pull request runs the quality gate in [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml). Pushes to `main` that pass are published to GitHub Pages (Settings → Pages → Source: **GitHub Actions**).
