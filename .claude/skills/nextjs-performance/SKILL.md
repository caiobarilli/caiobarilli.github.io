# Next.js performance for a static export

Adapted for this repository from [`nextjs-performance`](https://github.com/giuseppe-trisciuoglio/developer-kit/tree/fe73fb33a09ee6562eeec7415a3f9a3bcf795177/plugins/developer-kit-typescript/skills/nextjs-performance) by Giuseppe Trisciuoglio (MIT), at commit `fe73fb3`. The server-only parts (data cache, ISR, revalidation, route handlers, streaming data) were removed: this site has no server.

## What this site is

- `output: "export"`, `trailingSlash: true`, served as static files by GitHub Pages. Every page is HTML built ahead of time.
- `images: { unoptimized: true }`: Next does **not** resize or convert images. They are WebP files made by `scripts/shots.mjs` and `scripts/photo.mjs` (sharp, metadata stripped). Size and format are decided there, not at runtime.
- Fonts: Geist and Geist Mono through `next/font/google` in `src/app/fonts.ts`, self-hosted at build time.
- Content comes from `src/content/site.json` at build time. There is no fetch at runtime.

## Before changing anything

1. Build and serve the real output: `npm run build`, then serve `out/` (see `scripts/serve.mjs`).
2. Measure with Lighthouse (mobile) on the home, `/en/projects/` and the longest project page. Write down LCP, CLS, INP and total transfer size.
3. Fix the biggest number first. Measure again after the change. No change ships without a before and after.

| Symptom | Look at |
|---|---|
| LCP slow | The hero image and the fonts |
| CLS above 0 | Images without size or aspect ratio, late font swap, content injected after load |
| INP slow | Client components and their work on click |
| Heavy page | Image bytes first, then JavaScript |

## Images

- Use `next/image` with `width` and `height` (or `fill` inside a sized box) on every image, so the space is reserved and CLS stays at 0.
- **Next 16 deprecated `priority`.** For the one image that is the LCP (the hero on the home), use `loading="eager"` or `fetchPriority="high"`. Use `preload` only when exactly one image can be the LCP on every viewport. Never on several images.
- Everything below the fold stays lazy (the default).
- Because images are unoptimized, the file on disk is what the visitor downloads. Keep screenshots at the width they are shown at (about 1600 px for 16:10 shots) and check their weight in `public/images/` before committing.
- Give `sizes` when an image is not full width, so the browser picks well if responsive files are added later.

## Fonts

- Keep fonts in `next/font`. Never add a CSS `@import` or a `<link>` to Google Fonts.
- Only the `latin` subset. Add a weight or a family only if the design needs it, and measure the extra bytes.
- Fonts are exposed as CSS variables (`--font-geist`, `--font-geist-mono`) and used through Tailwind. Do not hard-code font names in components.

## JavaScript and client components

- Pages are Server Components by default. Add `"use client"` only for browser APIs or interaction, and keep it at the leaf: today that is `Header` (menu), `Lightbox`, `ProjectGrid` (filter), `ThemeSync` and `NotFoundContent`.
- A client component must not import `site.json` or other large modules. Pass it only the strings it needs as props.
- The theme script in `<head>` must stay tiny and inline: it runs before first paint to avoid a flash of the wrong theme.
- Prefer native elements (`<dialog>`, `<details>`) over a library. Do not add a dependency for something CSS or the platform already does.
- Load a heavy, below-the-fold client component with `next/dynamic` only if measuring shows it matters.

## Metadata

- Each page sets its own `title` and `description` through `metadata` or `generateMetadata`, in the page's language.
- The 404 keeps `robots: { index: false }`.

## Checklist before a release

- [ ] Lighthouse on mobile measured before and after, numbers in the commit or PR
- [ ] Every image has a size; only the LCP image loads eagerly; no `priority`
- [ ] New images generated by the scripts, in WebP, without metadata
- [ ] No new `"use client"` above a leaf, and no client component importing `site.json`
- [ ] No new runtime dependency without a measured reason
- [ ] `npm run gate` and `npm run test:e2e` green

## Not for this site

Data cache (`unstable_cache`, `revalidateTag`), ISR, route handlers, server actions, `useOptimistic` and Suspense streaming need a server. They do not apply to a static export. If the site ever moves off GitHub Pages, revisit the original skill.
